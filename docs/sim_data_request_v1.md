# 需要 sim 同学收集的信息清单 V1

状态：这是当前唯一还在阻塞"大批量生成"的东西，全部需要从 USD 环境里读，本仓库这边做不了。
按优先级排列，前两项不给就真的开不了工，后面的可以边收集边补。

## 必须要有（不给就没法定义 N02-N10 采样范围）

### 1. 每个候选物体的真实可达工作空间范围

已知：T01/T02/T03 三个物体各自的真实 bbox（来自 `preflight_report.json`），但这只是
"点"，不是"范围"。N02（物体位置偏移）需要的是：**以当前 nominal 位置为中心，物体在
xy平面上能挪动多大范围、双臂还能稳定抓到**。

最理想的产出方式：如果 `r1_bimanual_dataset/tools/scan_r1_reachability.py` 这个工具
（压缩包里看到过文件名，没看过内容）就是干这个的，直接跑一遍，把结果（一个可达区域的
边界，或者是"网格采样+成功率"的表）发我们。如果没有这样的工具，退而求其次：**给我们
5-10个不同 xy 偏移量的真实测试结果**（每个偏移量对应"抓取成功/失败"），我们从里面拟合
一个保守的采样范围。

### 2. 抓取/接近相关的容差范围

对应 N05（grasp offset）、N06/P22（approach angle）、N07/P21（pregrasp distance）。
`tools/calibrate_gripper_geometry.py`、`tools/calibrate_klt_grasp_pose.py` 这些工具
（压缩包里见过文件名）如果产出过类似"抓取点偏移多少还能成功"这种数据，直接把对应的
`reports/*.json` 发我们，不用重新跑。如果没有，需要的最小信息是：

- grasp offset：左右夹爪相对 nominal grasp frame 能偏移多少（单位：米），超过多少会
  触发抓偏（对应我们的 R12）
- approach angle：接近角度能偏多少度还能正常抓取
- pregrasp distance：预抓取距离的安全范围（下限：不会太早触发接触；上限：不会导致
  IK 解不出来或超时）

## 有更好，没有先不影响开工

### 3. 物体姿态扰动范围（N03/P23）

物体 yaw 能转多少度还抓得住——我们现在用的 P23 是 `object_yaw: 0.6`（约34度），纯粹
是拍的，不是算出来的。有真实数据最好，没有先用这个跑，后面再校准。

### 4. R15-R19 的真实阈值参数

现在 `configs/scenarios/r15-r19*.yaml` 里的 `slip_threshold_m`、`stall_time_s`、
`margin_min` 这些异常判定阈值都是我们估的，不是从真机标定出来的。如果 sim 同学的
`tools/` 目录下有 contact/force 相关的实测报告（比如 `small_klt_gripper_axis_report.json`
这种），可以用来校准这些数字，但不是当务之急——现在这些阈值在 Mock 测试里能跑通"检测
→恢复"这条逻辑链，真实数值偏差不影响架构对不对，只影响后面数据"逼真"不逼真。

### 5. 物体最终身份

现在还在用 T01/T02/T03 占位方块。如果已经决定继续用占位物体开工（大概率是，毕竟前面
决定"删除目标环要求"也是往"先用能跑的东西开工"这个方向走），这条可以先不用管，等
需要换正式物体（比如 Crew Lock Bag）时再单独走一轮场景对齐。

### 6. `coordination_mode`/`phase_offset` 的真实语义

我们已经把这两个字段加进 `ScenarioConfig`（字段名照抄了 sim 同学 `scenario_t03.json`
里已经在用的命名，不是我们自己发明的），但**这两个字段目前只是数据结构对齐，`episode_runner.py`
还没有真正按它们去驱动"一只手臂比另一只慢"这种行为**——这是我们这边的代码待办，不是
要问 sim 同学要数据，写在这里是为了不要漏掉。
